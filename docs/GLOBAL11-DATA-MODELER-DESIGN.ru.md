# Global11 — проектирование в Oracle SQL Developer Data Modeler

## Контекст проекта

Система Global11 была развёрнута и эксплуатировалась на офисном сервере под Oracle Global 11g. В материалах проекта также присутствуют дизайн `Global11_demo` для Oracle SQL Developer Data Modeler и описание последовательности построения его размерной модели.

Публичные источники подтверждают технический контекст примера Data Modeler. В статье от 13 января 2014 года Jeff Smith указывает, что в установку SQL Developer Data Modeler входил пример `global11_demo.dmd` и PDF с описанием построения модели. Связанная презентация Oracle 2013 года называется *Dimensional Modeling in Oracle SQL Developer Data Modeler*; на титульном слайде указан Philip Stoyanov.

- [Jeff Smith — Dimensional Modeling in Oracle SQL Developer Data Modeler (13 января 2014)](https://www.thatjeffsmith.com/archive/2014/01/dimensional-modeling-in-oracle-sql-developer-data-modeler/)
- [Philip Stoyanov — Dimensional Modeling in Oracle SQL Developer (презентация Oracle, 2013)](https://www.slideshare.net/slideshow/dimensional-modeling-in-oracle-sql-developer/29966332)

Метаданные дизайна Data Modeler, зафиксированные в материалах проекта: имя `global11_demo`, создатель `PSTOYANO`, дата создания `2012-12-12 04:59:41 UTC`, имя родительского дизайна `global11`. Эти поля идентифицируют запись дизайна, но сами по себе не определяют распределение задач по развёртыванию.

## Подготовка среды

Исходная инструкция описывает следующую последовательность:

1. Установить демонстрационную схему Oracle Global 11g `GLOBAL` по инструкции и архиву Oracle.
2. На этапе первоначальной подготовки схемы **не создавать Analytic Workspace**.
3. Для Oracle 12c выдать дополнительные привилегии:

```sql
GRANT CREATE VIEW,
      CREATE CUBE,
      CREATE CUBE DIMENSION,
      CREATE CUBE MEASURE FOLDER
TO GLOBAL;
```

4. Добавить в `GLOBAL.UNITS_FACT` поля `SHIP_MONTH_ID` и `DELIVERY_MONTH_ID`, первоначально заполнив оба значениями `MONTH_ID`.
5. Создать `GLOBAL.CUST_ACCOUNT` через CTAS, объединив `CUSTOMER_DIM` и `ACCOUNT` по `ACCOUNT_ID`.

Полный DDL и предостережения по выполнению приведены в документе [Подготовка Global11_demo](GLOBAL11-DEMO-SETUP.md).

## Последовательность построения модели в Data Modeler

В предоставленном описании зафиксированы следующие этапы:

1. Импортировать схему `GLOBAL` в SQL Developer Data Modeler.
2. Преобразовать реляционную модель в логическую.
3. Создать dimensional model.
4. Определить измерения, включая временные.
5. Определить уровни, ключи уровней, описательные и вычисляемые атрибуты.
6. Построить level-based hierarchies: связать измерение с базовым уровнем, затем соединить уровни в порядке roll-up.
7. Настроить joins и child-to-parent attributes, если уровни отображаются на разные сущности.
8. Определить value-based (parent-child) hierarchies через ключ уровня, родительский ключ и описательные атрибуты.
9. Обозначить пропуски уровней в ragged / skip-level hierarchy инструментом **New Ragged Hierarchy Link**.
10. Настроить dimension usage между кубами и измерениями, включая соединение факта с базовым уровнем и признаки role playing.
11. Определить кубы, фактовые сущности, меры и параметры предварительного вычисления.
12. Определить базовые и вычисляемые меры. Summary levels для базовых мер можно описать в модели, но исходная инструкция указывает, что они не экспортируются в Oracle OLAP.
13. Определить вычисляемые атрибуты уровней.
14. Экспортировать выбранную dimensional model и кубы в Oracle Analytic Workspace.

### Подтверждённые понятия размерного моделирования

| Понятие | Значение в модели Data Modeler |
| --- | --- |
| Dimension | Обычное или временное измерение с уровнями и иерархиями |
| Level | Уровень гранулярности, отображённый на сущность и имеющий ключ и описательные атрибуты |
| Level-based hierarchy | Путь roll-up от базового уровня к более агрегированным |
| Value-based hierarchy | Иерархия parent-child с ключом элемента и родительским ключом |
| Ragged hierarchy | Иерархия с пропуском одного или нескольких уровней |
| Dimension usage | Связь куба с измерением, включая атрибуты соединения факта с базовым уровнем |
| Role-playing dimension | Использование одного измерения в нескольких ролях факта; в Oracle OLAP для каждой роли создаётся отдельное измерение |
| Cube | Контейнер фактов, мер, связей с измерениями и срезов |
| Measure | Базовая мера, отображённая на атрибут факта, либо вычисляемая мера на основе выражения |

Ролевое использование времени иллюстрируется полями `MONTH_ID`, `SHIP_MONTH_ID` и `DELIVERY_MONTH_ID`. В исходной инициализации оба новых поля получают одно и то же значение. Это демонстрация role mapping, а не независимых дат отгрузки и доставки.

## Экспорт в Oracle Analytic Workspace

В исходных проектных заметках описано следующее поведение экспорта Data Modeler:

- Если Analytic Workspace с заданным именем уже существует, он удаляется и создаётся заново.
- Если задано имя файла, метаданные дополнительно экспортируются в файл.
- Даже экспорт только в файл требует подключения к Oracle Database: метаданные создаются в подключённой сессии, но не фиксируются в базе данных.
- **Default Schema** используется для разрешения объектов реляционной / физической модели, у которых явно не задана схема. Если Default Schema не указан, используется схема активного подключения.
- Можно выбрать, какие кубы включить в экспорт.

Это описание возможностей процесса, а не доказательство того, что Analytic Workspace был создан при историческом развёртывании. Первоначальная инструкция установки Global11 прямо исключает создание AW; экспорт из Data Modeler является отдельной осознанной операцией. Поэтому реляционное развёртывание, dimensional design и фактический экспорт/развёртывание AW документируются как разные состояния доказательной базы.

## Краткое описание проекта для резюме

**Oracle Global11 — моделирование данных и OLAP-архитектура**

- Работала с контекстом размерного проектирования в Oracle SQL Developer Data Modeler: преобразование relational-to-logical, измерения, уровни, roll-up и ragged hierarchies, dimension usage, role-playing time dimensions, кубы и меры.
- Документировала подготовку схемы Oracle Global 11g, проектные изменения SQL, структуры данных и процесс экспорта Data Modeler в Oracle OLAP.
- Разделила исторически развёрнутую реляционную платформу, размерный дизайн и OLAP-артефакты, runtime-развёртывание которых пока не подтверждено для портфолио.

**Технологии:** Oracle Database 11g / 12c · Oracle SQL Developer Data Modeler · Oracle OLAP · SQL · dimensional modeling · DMRS metadata · техническая документация.
